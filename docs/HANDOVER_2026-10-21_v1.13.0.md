## TL;DR for the next person

Four audit/security fixes are committed on `fix/audit-security-and-reliability` and pushed to GitHub. They are tested and work. They are NOT released to users yet because the first v1.13.0 release attempt had two problems:

1. **Splash screen didn't work** — the `expo-splash-screen` package wasn't installed, so the splash config in `app.json` did nothing. Phone still showed the default white flash with circle/lines.
2. **First APK was signed with the debug key** — because `expo prebuild --clean` wiped the keystore config and the `SigningConfig` plugin wasn't installed yet. Android refused to install over the production v1.12.0 (signature mismatch).

We rebuilt with the right signing key, but by then the user (who has had a TBI and struggles with context) was exhausted. We rolled back: deleted the v1.13.0 release and git tag. Production is back to v1.12.0. The audit fixes are safe in the branch.

## Honest limitations / known issues

- **Rate limit is per-gunicorn-worker.** Render runs 2 workers, so the effective cap is 20/hour per device, not 10. Documented in code. A real fix needs Redis; out of scope for this audit pass.
- **Splash config requires `expo-splash-screen` package.** This was the bug that caused the rollback. The package needs to be installed before the next build.
- **`expo prebuild --clean` wipes the keystore files.** The `SigningConfig` plugin fixes this by patching `android/app/build.gradle` to look in the right place. The keystore files themselves still need to be manually restored from `C:\FrogPaperBackups\keys\` after each prebuild.
- **Android still shows a brief cold-start window** before the splash screen. This is unavoidable — Android shows the system cold-start window while the app process is starting, then Expo's splash screen takes over once the JS bundle loads. So expect: brief white flash (sub-second) → frog on dark purple (1-2s) → app.
