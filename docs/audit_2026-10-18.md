# FrogPaper Mobile — Full App Audit

**Date:** 2026-10-18  
**Audited commit:** `1931fe2` (`main`, after the BYOK provider-status merge)  
**Audit branch:** `fix/audit-security-and-reliability` (code commit `897e163`; handoff docs added after it)  
**Scope:** React Native / Expo mobile app, Flask backend, storage, tests, build configuration, and the main user flows.

---

## Executive summary

The app is in good shape structurally: it builds for web, the backend imports and serves correctly, and **713 mobile headless checks** pass across 14 of 16 suites. The core generation, gallery, prompt builder, rotation, and offline queue logic is well covered by pure-function tests.

The audit still found several real problems that the existing checks did not catch:

- **Every “Generate again / Edit / Use this prompt” path from Detail, History, and Build was broken** by the bottom-tab refactor. Those screens are on the root stack and called `navigate('Generate')`, which the root stack does not contain. The button silently did nothing. **Fixed.**
- **The remote delete endpoint had no ownership check.** Any install that knew a filename could delete another install’s image. **Fixed.**
- **Prompt history was global.** `/api/prompts/recent` merged every install’s prompt text. **Fixed.**
- **The Android wallpaper setter reported success on native failure.** It only checked `result.error`, while the native module reports `{ status: 'error', msg }`. A failed wallpaper change was shown as “Wallpaper updated.” **Fixed.**
- **`/api/health` rebuilt the entire gallery on every poll.** The container health check and the GitHub keepalive workflow hit it constantly. **Fixed with a cheap count.**
- **The Slideshow screen is unreachable, non-functional, and global across users.** It never calls `setAsWallpaper`, and its config is one server-wide file. **Not fixed — needs a product decision (finish or remove).**
- **BYOK keys are stored in plain AsyncStorage**, prompts are written to server logs, and there is no rate limiting. **Not fixed — recommended next.**

## Fixed in the audit branch

### 1. Restored every screen-to-Generate handoff

**Files:** `DetailScreen.js`, `HistoryScreen.js`, `PromptBuilderScreen.js`, `SlideshowScreen.js`

The root stack contains `Tabs`, `Build`, `Detail`, `Slideshow`, and `History`. It does **not** contain `Generate`. `navigation.navigate('Generate')` from any root-stack screen is not handled by the root stack and is not searched downward into the tab navigator.

The fix routes through the tab navigator and pops the root stack back to the existing Tabs route:

```js
navigation.navigate(
  'Tabs',
  { screen: 'Generate', params: { ... } },
  { pop: true }
);
```

`pop: true` is important: without it, the stack router pushes a second Tabs instance instead of returning to the existing one. Added `scripts/check-navigation.js` so this specific regression cannot slip through again.

This affects:
- Detail → Generate again
- Detail → no-prompt handoff notice
- History → Make again / Edit
- Build → Use this prompt
- Slideshow → Gallery

### 2. Closed cross-device gallery leaks

**File:** `backend/app.py`

- `DELETE /api/gallery/<filename>` now requires the same device ownership as `GET /api/gallery/<filename>` and `GET /api/images/<filename>`.
- `GET /api/gallery` now filters the already-enriched entries by `entry["device"]` instead of re-reading every sidecar through `_owns_image()`.
- `GET /api/gallery/<filename>` now reads the entry once and checks its `device` field.
- `GET /api/prompts/recent` now passes the requesting device id into `recent_prompts()`, so prompt text is never merged across installs.
- `/api/images/*` now sends `Cache-Control: private, max-age=86400` instead of `public`, so shared caches cannot retain one install’s private wallpaper.

New regression suite: `backend/tests/test_multiuser_isolation.py` — 18 checks covering gallery lists, detail, prompt history, delete, and health.

### 3. Made `/api/health` cheap

**Files:** `backend/app.py`, `backend/services/storage.py`

`/api/health` used `IMAGE_STORAGE.list_images()`, which enriches every image by reading its sidecar and potentially fetching up to 512 KB of image header. The endpoint is polled by the app, the Docker health check, and the GitHub keepalive workflow.

Added `ImageStorage.count_images()`, which counts valid image objects from storage metadata only. The new test monkey-patches `read_sidecar` and proves health reads **zero** sidecars.

### 4. Fixed the Android wallpaper false-success

**File:** `mobile-app/src/services/deviceMedia.android.js`

The native module reports:

```js
{ status: 'success' | 'error', msg, url }
```

The JS wrapper only checked `result.error`. It now treats `result.status === 'error'` as a failure and surfaces `result.msg` to the caller. This fixes the misleading “Wallpaper updated” message in Detail, Generate, Gallery, daily rotation, and shuffle flows.

### 5. Fixed the Gallery focus spinner

**File:** `mobile-app/src/screens/GalleryScreen.js`

`useFocusEffect` captured `images.length === 0` from the first render and never saw later images. Every return to the Gallery tab called `load(true)` and showed a full-screen spinner even when the grid was already populated. Replaced the stale closure with an `imageCountRef`.

### 6. Prevented duplicate queue runs

**File:** `mobile-app/src/services/generationQueue.js`

Home’s automatic queue run and Generate’s “Run queued” button could process the same snapshot concurrently, generating and paying for the same prompt twice. Added a module-level in-flight promise; the second caller joins the first run.

### 7. Scoped BYOK headers to the endpoints that need them

**File:** `mobile-app/src/services/api.js`

`X-Gemini-Key`, `X-Hf-Token`, and `X-Replicate-Token` were attached to every API request, including health, gallery, prompts, slideshow, and upload. They are now attached only to `/api/providers` and `/api/generate`. The upload path also now waits for the access-key preload, closing a first-upload 401 race.

### 8. Removed the invalid Expo config field

**File:** `mobile-app/app.json`

`android.usesCleartextTraffic` is not a valid Expo config field; the custom `WallpaperManagerFix` plugin already sets it on the generated manifest. Removing it makes the Expo config schema pass. The plugin remains the source of truth.

## Remaining findings, prioritized

### High / product

**1. Slideshow is dead code and does not do what it says.**  
`SlideshowScreen` is registered in `AppNavigator` but no screen navigates to it. It never calls `setAsWallpaper`; it only displays the current image and offers a Save button. Its config is a single server-wide `slideshow_config.json`, and `/api/slideshow/next` cycles through **all** images, not the caller’s images. The JS timer only runs while the screen is mounted, so it cannot change the wallpaper in the background.

Options: remove the screen until it can be built properly, or rebuild it as a per-device foreground feature with explicit “keep FrogPaper open” wording, device-filtered images, and a real `setAsWallpaper` call on each interval.

**2. BYOK keys are stored unencrypted.**  
`api.js` keeps Gemini/HF/Replicate keys in AsyncStorage. AsyncStorage is app-sandboxed but not encrypted; on a rooted device or a backup extraction they are readable. `expo-secure-store` is the right place for them, with a one-time migration and a web fallback.

**3. Prompt text is written to server logs.**  
`backend/app.py` logs `prompt[:60]` on every generate request. Prompts can contain personal or sensitive text. Log only length, a hash, or a redacted marker in production.

**4. No per-device rate limiting.**  
The access key ships inside the app, so anyone can extract it. `/api/generate` has no token bucket; a single client can burn Pollinations quota or a server-side provider key. Add a small in-memory per-device/IP limit (e.g. 10 generations/hour) and return 429 with a retry time.

### Medium

**5. Gallery listing is still expensive at scale.**  
`list_images()` reads every sidecar and may fetch up to 512 KB of header per image before the route applies `limit`/`offset`. On S3 with a large gallery this is many requests per load. Improvements: paginate at the storage layer, prefer width/height stored in the sidecar, reduce `DIMENSION_HEADER_BYTES` to 64 KB, and cache the listing for a short TTL.

**6. Gallery delete-undo race.**  
Deleting image A, then image B within 5 seconds, clears A’s timer and leaves A hidden forever without deleting it. Commit the previous pending delete before arming the next one, or keep a queue of pending deletes.

**7. `shareWallpaper` leaks cache files.**  
`share.js` downloads the image to the cache root and never deletes it. `pruneToMax` only prunes the `wallpapers` cache subdirectory. Delete the temp file in a `finally` block after the share sheet resolves.

**8. Health count is global.**  
`images_count` counts every install’s images. Home uses it for “N wallpapers on the server,” which can show other users’ total. Use a generic “Server gallery” label or a per-device count from `/api/gallery`.

**9. Upload has no timeout.**  
`api.uploadImage` calls `expoFetch` without an AbortController. A stalled upload can spin indefinitely. Add the same 60–180 s timeout used by `request()`.

**10. Custom-patched 2016 native library.**  
`react-native-wallpaper-manager@0.3.16` is patched at prebuild time by `WallpaperManagerFix.js`. It works today, but every Expo/RN upgrade is a potential build break. A small first-party native module (BitmapFactory + WallpaperManager) or a maintained library would be more durable.

**11. Overbroad transport/permission settings.**  
`NSAllowsArbitraryLoads: true` on iOS and cleartext HTTP on Android are useful for LAN development but should not be enabled in production builds. `READ_MEDIA_VIDEO` and `READ_MEDIA_AUDIO` are not used by the app. Prefer `NSAllowsLocalNetworking`, a debug-only cleartext config, and image-only permissions.

### Low / tooling

**12. `check:sentry` is misleading.**  
Sentry is intentionally disabled because its native plugin does not build with Gradle 9. The check still expects the Expo plugin and fails; `SettingsScreen` still contains dead Sentry handlers/state, and `react-native.config.js` claims JS Sentry still works while `sentry.js` is all no-ops. Either remove Sentry entirely until it is supported, or make the check report “disabled” and delete the dead code.

**13. `check:versions` fails on a clean clone.**  
It reads `android/app/build.gradle`, but `android/` is generated and gitignored. Skip the Gradle comparison when the file is absent, or run it only after prebuild.

**14. Expo dependency drift.**  
`expo-doctor` reports 8 patch-level Expo packages behind and a major mismatch for `@sentry/react-native` (expected ~7.11, found 6.10). Run `npx expo install --check` and upgrade the patch-level packages in a branch, then rebuild and device-test. `axios` is also in `dependencies` but unused.

**15. Docs and version numbers are stale.**  
The backend reports `APP_VERSION = "1.9.45"` while the app is 1.12.0. `docs/START_HERE_TOMORROW.md` says 693 checks and that `check:sentry` is skipped; the crash-log item is listed as “not started” even though `errorLog.js` exists. Update these before the next release.

**16. No CI for tests or builds.**  
The only workflow is the backend keepalive. Add a PR workflow that runs the backend test scripts, `npm run check:*` (excluding the two known tooling failures), and `npx expo export --platform web`. That would have caught the navigation regression and the BYOK status bug.

## Suggested next steps

1. **Merge the audit branch** and device-test: Build → Generate, Detail → Generate again, History → Make again, Gallery focus, Android wallpaper success/failure.
2. **Decide Slideshow:** remove it from the navigator until it can actually set wallpapers, or rebuild it with per-device config and device-filtered images.
3. **Security pass:** move BYOK keys to SecureStore, redact prompt logs, add rate limiting, and restrict cleartext/arbitrary-loads to debug builds.
4. **Performance pass:** paginate storage listings, reduce dimension-header reads, and cache the gallery list.
5. **CI + release hygiene:** add the test/build workflow, fix the two check scripts, and update the stale docs/version strings.
