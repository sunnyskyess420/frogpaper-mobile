# Handover - 2026-09-10

Rebuild, hardening and live verification of the FrogPaper Mobile project,
performed in a sandbox against the real Pollinations.ai service and a real
headless browser. This document explains what changed since the previous
handover, what was verified, and how to get everything running on your
Windows machine.

## What was done

### 1. Backend rebuilt and hardened (drop-in replacement)

Same five endpoints and same response style as before, plus:

- **CORS enabled** for `/api/*` - fixes the Expo web client being blocked
  cross-origin (it runs on `:8081`, API on `:5000`).
- **Retries with backoff** - Pollinations calls retry 3 times before
  failing; read timeout raised to 120s.
- **Structured JSON errors** on every failure path, including Flask-level
  404/500 handlers - the app never has to parse an HTML error page.
- **Input validation** - prompt length 3-600 chars, width/height clamped
  to 256-2048, seed clamped, unknown provider rejected with 400.
- **Path traversal guard** on the image-serving route (basename only).
- **Extension-aware saving** - provider's content type decides
  jpg/png/webp; unique timestamped filenames.
- Gallery metadata (dimensions, size, created_at) computed cheaply with
  header-only PIL reads and cached per file.

### 2. Mobile app rebuilt on current tooling

- **Expo SDK 57 / React Native 0.86 / React 19** (previous code targeted
  older versions - a likely cause of the "Expo starts but never responds"
  symptom together with partially installed web deps).
- React Navigation v7 (native-stack), all four screens rebuilt with a
  consistent dark frog-green theme.
- **Automatic backend URL resolution** in `src/services/api.js`:
  - web -> `http://localhost:5000`
  - Android -> tries `http://10.0.2.2:5000` (emulator alias), then LAN IP
    `10.2.0.2:5000`, then localhost
  - iOS -> tries LAN IP, then localhost
  Detection is a live `/api/health` probe per candidate, so no manual
  URL switching when you move between web, emulator and phone.
- Generate screen: prompt input with counter, size presets, inspiration
  chips, loading state, error card, result card with preview and
  "Open gallery" / "Generate again".
- Gallery screen: 2-column grid, pull-to-refresh, empty state, tap for
  fullscreen viewer.
- Settings screen: live connection status with re-test button, provider
  info, about section.

## Old known issues -> resolution

| Old issue | Root cause | Status |
|-----------|------------|--------|
| "Expo server starting but not fully responsive" | Mixed SDK versions + web deps half-installed + cache | Rebuilt on a consistent SDK 57 dependency set; restart with `npx expo start --clear` if it ever recurs |
| "API URL set to localhost, needs 10.0.2.2 for emulator" | Hardcoded URL | Auto-resolver probes candidates per platform - nothing to edit in normal use |
| "react-dom / react-native-web just installed" | Version drift risk | Locked, SDK-matched versions in `package.json` (installed via `expo install`) |

## Getting this onto your PC

The repo `https://github.com/sunnyskyess420/frogpaper-mobile` now contains
this tested tree. On Windows:

```powershell
cd E:\FROGPAPER
git clone https://github.com/sunnyskyess420/frogpaper-mobile.git FrogPaperMobile-tested
cd FrogPaperMobile-tested\backend
python -m venv venv
.\venv\Scripts\activate
pip install -r requirements.txt
python app.py
# second terminal:
cd E:\FROGPAPER\FrogPaperMobile-tested\mobile-app
npm install
npx expo start --web
```

Prefer your original folder? Clone or download the ZIP and copy these three
things over your existing `E:\FROGPAPER\FrogPaperMobile\`:

- `backend/app.py`, `backend/services/`, `backend/requirements.txt`, `backend/test_generation.py`
- the whole `mobile-app/` folder (except `node_modules/` - run `npm install` after)
- this `docs/` folder if you want the reference material

**Your 82 existing wallpapers:** copy them into
`backend/static/images/` (keep the originals as backup). The gallery picks
them up automatically - no database, no import step.

If you edited any screens locally and want to keep those edits, do not
overwrite them blindly - diff against the new files or ask for help merging.

## Recommended first test session on your PC

1. Start backend, open `http://127.0.0.1:5000/api/health` in a browser.
2. `npx expo start --web` -> Home should say **Backend online** with your
   image count.
3. Generate tab -> tap an inspiration chip -> Generate -> wait up to a
   minute -> result card appears.
4. Gallery tab -> pull to refresh -> your new image is at the top.
5. Android emulator: press `a` in the Expo terminal (backend must be
   running). No URL edits needed.
6. Physical phone: Expo Go, scan QR, same Wi-Fi. If it says offline,
   check `LAN_IP` in `mobile-app/src/services/api.js` against `ipconfig`
   and allow Python through Windows Firewall.

## Session update (same day): Moves 1 & 2 shipped

Two roadmap moves from `PLAN_STATUS.md` landed after this handover was
written, both live-verified in the sandbox browser:

**Move 1 - Gallery management** (backend + UI)

- New endpoints: `POST /api/gallery/upload`, `GET /api/gallery/<file>`,
  `DELETE /api/gallery/<file>` - 10/10 API checks passed.
- DetailScreen with metadata card + delete-with-confirm; upload button in
  Gallery; the list silently refreshes whenever the tab regains focus.

**Move 2 - Save to device + set wallpaper (Phase 4.1)**

- "Save to device" on the Detail screen and on the generation result card.
  Platform-split service (`src/services/deviceMedia.{web,android}.js` +
  iOS default): web downloads via an object-URL anchor (verified with real
  files landing in the downloads folder), native saves through
  `expo-media-library` after a cache download (new `expo-file-system` API).
- Android "Set as wallpaper" wired through `react-native-wallpaper-manager`
  behind a platform-split module: inside Expo Go it degrades gracefully
  with guidance instead of crashing; a development build activates the
  direct call - see `docs/DEV_BUILD.md`. Not yet verified on real hardware.
- `app.json` gained the `expo-media-library` plugin (permission text) and
  an iOS local-network ATS exception for development against the PC backend.

**Next move:** prompt builder upgrade (structured presets, negative prompt,
generation history).

**Move 3 - Prompt builder upgrade** (shipped same session, verified API + UI)

- Generate screen: 7 style preset chips (Photorealistic, Cyberpunk, Pastel,
  Fantasy, Minimalist, Oil painting, Anime) that append proven descriptor
  phrases; an "Avoid (optional)" negative-prompt field with an honest hint
  that Flux only takes it as soft guidance; "Recent prompts" chips that
  refill the prompt (and negative) with one tap - ideas list remains as
  the fallback when history is empty.
- Detail screen now shows Seed, the full Prompt, and the Avoided text.
- Backend: prompt + negative + seed + model persist in sidecar JSON files
  (`pollinations_<stamp>.json`, no database); new endpoint
  `GET /api/prompts/recent`; DELETE cleans up sidecars; uploads record
  their original filename too. `negative_prompt` accepted by
  POST /api/generate (validated to 300 chars).
- Verified: 6/6 API checks (incl. real generation with a negative prompt,
  sidecar persistence, recent list, validation, delete cleanup) and a full
  browser pass (style chip selected -> suffix stored in prompt -> detail
  shows it -> recent prompts appears -> tap-to-reuse refills the input).
